## What the App Does

NPS Photo Collector is a single-file Progressive Web App (all HTML/CSS/JS in `index.html`, no build step) for National Park Service Environmental Audit Program field work, used by HGS Engineering auditors. Each entry captures a park + location (picked from the bundled facility list with GPS distance sorting, park auto-detect and nearest-location auto-suggest), an EnviroCheck question (searchable index of 810 questions with sheet filter chips, synonym matching, ranking hints and recent picks) which fills in the sheet and suggests the priority and description code, a **priority 1 / 2a / 2b / 3 / 4 / P** (required), an optional **repeat-of** link to a finding in the previous audit, a description, GPS coordinates with accuracy, and any number of photos (camera or library, client-side compressed, written through three-tier durable storage with verified writes and an integrity badge).

Two exports share the same date filter and missing-photo guard:

- **Export ZIP** — renamed photos (`MMDDYY_Location_PARKCODE_NNNN.jpg`, numbered in finding order), a CSV, and an Excel workbook: Audit Summary, one WASO-layout Audit Report sheet per park (columns A–S paste straight into the official findings spreadsheet), the raw NPS Entries, SPCC Tank Check and Personnel. Stamps entries as exported and offers a post-export batch delete.
- **Word Report** — a `.docx` photo log per park in finding-number order: each finding's header (number, priority, sheet, location, description, question, repeat note), then its photos one per row at the same numbers the ZIP gives them, or "No Photo Available". Audit team and personnel tables at the end. A report only: it never stamps entries or offers deletion.

## Current Capabilities

- Offline-first PWA on Azure Static Web Apps (auto-deploy from GitHub `main`)
- Region → Park → Location picker over 449 park units / 43,026 locations, GPS Nearby filtering, park auto-detect, nearest-location auto-suggest
- EnviroCheck question search: 810 questions from the 17 federal sheets, sheet filter chips, synonym matching, phrase ranking hints, recent picks, priority (P1–P4) shown on every result; picking a question sets the sheet and suggests priority + description code
- Priority scoring 1 / 2a / 2b / 3 / 4 / P (required to save; red / orange / green like the report legend), plus **Note** for a general observation that is not a finding (no sheet or code; its own Field Notes sheet and a notes block in the Word log), the ten WASO description codes, park code on every entry
- Prior-audit import (WASO findings `.xlsx`), browse by park and sheet, mark an entry as a repeat (auto-bump 2b → 2a), repeat citation in the export
- Photo capture/import with configurable compression, unlimited slots, verified three-tier durable storage, integrity badge
- ZIP export (photos + CSV + workbook with Audit Summary and per-park WASO Audit Report sheets) and per-park Word photo log, both date-filtered and both blocked on missing photos
- **SPCC tank check:** import the park's Tables 1-3 Word file straight into the app, then mark each tank Confirmed / Discrepancy / Not found with corrections, notes and photos, add containers found on site, and promote a problem to a finding by hand. Exports as an SPCC Tank Check sheet with photo numbers continuing the ZIP's own sequence
- **LOC / EDL sites:** per Location of Concern, photos with a caption and the direction the camera faced (or tagged as the location map or aerial), GPS, and the EDL form's field rows as tap buttons. The ZIP carries a LOC Sites sheet and one EDL site data form per site with the picked answers highlighted and the database rows left for the office
- **Notes document:** the ZIP also carries a Word file listing only the field notes, per park, with the same photo numbers as the workbook
- **Team & personnel:** audit team (name + organization), NPS regional coordinator, and park personnel contacted — a Personnel sheet, the Audit Summary header, and tables at the end of the Word report
- Storage usage bar, previous-day reminder, JSON backup/restore (tank list, personnel, audit team and prior audit included)
- NPS brown header/accent so it is visually distinct from the green USFS app on the same device

## Open Items / Decisions to Confirm

- **EDL database fields** (site ID, phase, sub-phase, type, ownership, jurisdiction, contaminants, social impact, funding, cost recovery, impairment) are left for the office on the exported form. An import of the EDL database's site list could pre-fill them once a sample export is available.
- **Storage warning at 40 MB** is the app's own reminder to export, inherited from the USFS app; nothing is blocked at 40 or 80 MB and the browser quota is far larger. The real exposure is data that has not been exported yet.
- **Left for the office by design:** recommended corrective action, estimated completion date, responsible party, other sources, and the park-side columns are exported blank. Say the word if any should be captured in the field after all.
- **Acadia's bundled location list has no maintenance facilities** (the NPS public POI data covers visitor-facing points: restrooms, parking, visitor centers, campgrounds). Type shop and yard names by hand; the park code still comes from the selected park.
- **Port candidates for the USFS app** (same shared code): the phone-width question dropdown (one scrollable chip row, 60vh list), `esc()` on the saved-list rows, the `&`/`"` escaping in the location picker's `onclick`, `closest('.form-group')` instead of `:has()` for Safari 15.0–15.3, and the phone-width `min-width: 0` on the flex selects; `shareOrDownload()` returning false on a cancelled share sheet (callers stop instead of claiming success), the fallback-photo purge limited to shipped keys, the JSZip guard in `runExport()`, and the saved-list date filter (`savedFilterMatch()` in `renderSavedPanel()`); from v2.9, all of which are shared-code fixes: `saveEdit()` finding its target by id, `deleteEntry()`/backup import leaving edit mode cleanly, `addPhotoSlot()` never reusing a slot id, the `loadAll()` guard against non-array saved entries, `checkStorage()` using the browser's real quota, the photo viewer (`onPhotoTap`/`showPhotoViewer`), `confirmDelete()` on every destructive action, and the removal of the post-export delete prompt.
- **Finding numbers are assigned at export time** after the WASO sort (park, priority, sheet, citation, location), so they shift if the exported set changes — the same rule the office applies for the final numbering. Photo numbers follow the same order.
- **Description code suggestions** are keyword rules over the question wording (`DESC_CODE_RULES`); they are a starting point, not a classification. Tune the rules if a sheet keeps suggesting the wrong code.
- **Citation source buckets** in the Audit Summary put NFPA and state statutes under "State / local / other"; the report's dashboard may want NFPA elsewhere.
- **Question code format** was chosen here, not given: questions are numbered `<SHEET>.<NN>` (e.g. `UO.05`, `SPCC.02`, `HW.01`) following each sheet's own question numbering.
- The EnviroCheck sheets are the **2017 federal editions** only. There are no state supplements in the set, and the sheets do not cover NPS-specific policy (for example bear-resistant containers), so those searches find nothing.
- Midwest-region NPS GIS data is largely unnamed; about 1,000 locations carry synthesized names like `Campground (unnamed)`. The NPS Data API (free key) could backfill named facilities.
- The Word report embeds photos through docx 8.2.2, which names every embedded image `.png` regardless of format. Word reads the JPEG bytes correctly (the DLA tool has shipped this for months), but a future docx upgrade should be checked against Word.
